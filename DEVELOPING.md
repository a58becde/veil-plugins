# Как сделать плагин и выставить его в маркет

Путь от пустого каталога до плагина в `/market` у всех ботов Veil — своих и в пуле. Справочник API (события, функции,
разрешения) — [`docs/PLUGINS.md`](https://github.com/a58becde/veil-client/blob/main/docs/PLUGINS.md) клиента,
устройство движка и форматы каталога — [`docs/MARKET.md`](https://github.com/a58becde/veil-client/blob/main/docs/MARKET.md).

## 0. Что понадобится

- Linux (с Landlock, ядро 5.13+) или macOS, x86_64 или aarch64. Плагин работает в движке WebAssembly, проверять его
  нужно в нём же — движок одинаковый у всех ботов.
- Python 3.11+, libsodium, git.
- Свой бот Veil — только на последнем шаге, проверить плагин вживую. Писать и отлаживать можно без бота и без сервера.

```sh
git clone https://github.com/a58becde/veil-client.git && cd veil-client
python3 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements.lock && .venv/bin/pip install --no-deps -e .
.venv/bin/python -m veil.plugin_engine fetch      # официальный движок (18 МБ, хеш сверяется)
```

## 1. Пакет

Каталог с именем плагина и двумя файлами:
```
hello/
  plugin.toml
  main.py
```
```toml
id = "hello"                      # = имя каталога: a-z, 0-9, _, до 32 символов, с буквы
name = "Привет"
version = "1.0.0"                 # X.Y.Z; каждая публикация — новая версия
api = 1
entry = "main"                    # main.py
description = "Здоровается по команде /hello"
author = "Ваше имя или ник"
license = "MIT"                   # лицензия кода (SPDX)
permissions = ["commands", "notify"]
# network = ["api.example.com"]   # только вместе с разрешением "net"
# price_stars = 0                 # платный — цена в Telegram Stars (раздел 7)
# author_pk = "…"                 # ключ автора — появится на шаге 5; локально можно без него
```
```python
from veil import plugins

STORE = plugins.storage()         # своё хранилище (JSON до 1 МиБ), переживает перезапуск


@plugins.on_command("hello", "Поздороваться")       # вход в плагин: команда без аргументов
async def hello(arg: str) -> None:
    await plugins.show("Как поздороваться?", [plugins.Button("Просто", "hi"),
                                             plugins.Button("По имени", "hi_name")])


@plugins.on_button("hi")
async def hi(press: plugins.Press) -> None:
    n = STORE.get("n", 0) + 1
    STORE.put("n", n)
    await plugins.edit(press.message, f"Привет! ({n}-й раз)")   # экран меняется на месте


@plugins.on_button("hi_name")
async def hi_name(press: plugins.Press) -> None:
    await plugins.ask("Как вас зовут?", "name")              # ответ придёт следующим сообщением


@plugins.on_input("name")
async def got_name(text: str) -> None:
    await plugins.notify_owner(f"Привет, {text}!")
```

**Интерфейс — кнопками, а не аргументами команд.** Команду в меню Telegram нажимают, и она уходит сразу: дописать
к ней ничего нельзя. Команда — только вход; дальше `show`/`edit` с кнопками, `ask` для текста, а если плагин работает со
ссылками на какой-то сайт — `@plugins.on_link("сайт", label="…")`: владелец просто присылает ссылку, под черновиком
появляется кнопка плагина. Подробно — `PLUGINS.md`, «Кнопки и вопросы».

Все обработчики — `async def`. Какие события и функции есть и какое разрешение нужно каждой, — в таблицах
`PLUGINS.md`. Просите только нужные разрешения: чувствительные (`private`, `published`, `before_send`) и особенно
чувствительное вместе с `net` ревью пропустит только с убедительной причиной.

### Ограничения движка

| Что | Как |
|---|---|
| Запуск | **каждое событие — новый запуск модуля**: переменные модуля между событиями не живут, помнить — в `plugins.storage()` |
| Порядок | события плагина у одного бота идут по очереди; обработчик видит хранилище таким, каким его оставил прошлый |
| Ожидание | вызовы бота возвращаются сразу; `asyncio` в движке нет, ждать чужого ожидания нельзя |
| Библиотеки | стандартная библиотека — только модули для данных (`json`, `re`, `datetime`, `html`, `urllib.parse`, `hashlib`…, список — `PLUGINS.md`); сторонних нет |
| Сеть | сокетов нет; HTTPS — только `plugins.http` к хостам из `network`, ответ до 4 МиБ |
| Файлы | нет; данные — `plugins.storage()` (JSON до 1 МиБ) |
| Время и память | событие — 30 с, команда — 120 с, `before_send` — 10 с; 64 МБ памяти на событие |
| Частота | `notify_owner` 20/мин, `propose_draft` 10/мин, `http` 60/мин, запись в хранилище 120/мин |
| Пакет | плоский каталог: только `plugin.toml`, `*.py`, `README.md`; до 64 файлов и 1 МиБ |
| Вывод | `print` уходит в журнал бота, владельцу не показывается |

Что плагин не может в принципе: изменить пост (бот публикует ровно то, что прислал владелец), опубликовать без
«Отправить» владельца, узнать Telegram ID владельца, токен бота, ключи и 12 слов.

## 2. Проверка без бота

```sh
.venv/bin/python -m veil.plugin_dev путь/к/hello
```
Плагин запускается в том же движке, что у бота; вместо Telegram — консоль. Подавайте события командами:
```
/hello                      команда плагина (как нажатие в меню)
press 2                     нажать кнопку 2 последнего сообщения плагина
input Вася                  ответить на вопрос плагина
link https://example.com/1  прислать ссылку — нажать кнопку плагина под черновиком
reply 5 текст ответа        ответ на ваш пост №5 (on_reply)
private текст               «лично для» вас (on_hidden_for_me)
published 12                ваш пост вышел (on_post_published)
error post.create E_RATE    действие не выполнено (on_error)
tokens 3                    токенов осталось мало (on_tokens_low)
send текст поста            пропустит ли before_send
```
Ответы плагина печатаются строками `→ владельцу:`, `→ сообщение #N:` (с кнопками `[1] …`), `→ правка #N:`,
`→ вопрос:` и `→ черновик:`, сбои — `✗` и строкой журнала с причиной.
Настройки плагина — `--settings=файл.toml`, хранилище между запусками — `--data=каталог`. Для автоматической проверки
(CI) — `--script=файл` с командами по строке: код возврата 1, если пакет не запустился или обработчик упал.

Частые ошибки при запуске: `id` не совпадает с именем каталога; файлы доступны на запись группе (`chmod -R go-w`);
событие без разрешения в манифесте; `import` сторонней библиотеки или модуля, которого нет в движке (сообщение
«модуля … нет в движке плагинов»); счётчик в переменной модуля (обнуляется каждое событие — нужен `storage()`).

## 3. Проверка в своём боте

Поставьте свой бот по [`docs/INSTALL.md`](https://github.com/a58becde/veil-client/blob/main/docs/INSTALL.md), затем:
```sh
mkdir -p plugins && chmod 700 plugins          # рядом с config.toml бота
cp -r путь/к/hello plugins/ && chmod -R go-w plugins/hello
```
В `config.toml`: `[plugins] enabled = ["hello"]`; перезапустите бота. Бот спросит согласия на разрешения — «Разрешить».
После правки кода бот сообщит «~ изменён» и снова спросит согласия, если разрешений стало больше.

## 4. Перед публикацией

- Описание честное и понятное владельцу бота: что делает плагин и зачем ему каждое разрешение.
- `README.md` в пакете — по желанию: его увидит ревьюер.
- Версия — новая для каждой публикации (`1.0.0` → `1.0.1`).

## 5. Ключ автора, упаковка, подпись

Ключ автора создаётся один раз. Им подписываются все версии плагина; обновление другим ключом боты не поставят, так что
храните ключ как пароль и с копией.
```sh
.venv/bin/python -m veil.market_tool keygen ~/veil-author.key       # печатает публичный ключ
```
Публичный ключ — в `plugin.toml` (`author_pk = "…"`), затем:
```sh
.venv/bin/python -m veil.market_tool pack путь/к/hello hello-1.0.0.zip
.venv/bin/python -m veil.market_tool sign hello-1.0.0.zip ~/veil-author.key   # → hello-1.0.0.zip.sig
```
`pack` собирает архив детерминированно (одинаковый код — одинаковый SHA-256) и отказывает, если в каталоге лишнее.

## 6. Подача в каталог

**Бесплатный плагин** — pull request в этот репозиторий: `submissions/hello-1.0.0.zip` и
`submissions/hello-1.0.0.zip.sig`, в описании — что плагин делает и зачем ему каждое разрешение. `index.json` не
трогайте: его пересобирает ревьюер.

**Платный** — архив **не** в pull request (репозиторий публичный, история git хранит файл навсегда): `zip` и `zip.sig`
лично владельцу каталога, в pull request — только описание и `plugin.toml`.

Ревью — по чек-листу README: код читается целиком, разрешения минимальны, хосты `network` объяснены, в обновлении
читается разница с прошлой версией. После принятия плагин появляется в `/market` у всех ботов при ближайшем
обновлении каталога.

## 7. Платный плагин

- Цена — `price_stars` в манифесте (Telegram Stars). В каталоге лежит только зашифрованный пакет; описание, манифест и
  разрешения открыты, чтобы покупатель видел, что покупает.
- Покупатель платит в боте-магазине проекта и получает лицензию на один свой бот с обновлениями: следующие версии он
  ставит без новой оплаты. Магазин знает, кто купил, но не знает, в каком боте стоит плагин.
- Возврат денег лицензию не отзывает (технически невозможно), поэтому условия возврата — в `/terms` магазина.
- Сводка продаж по плагину — у владельца каталога. **Условия выплат авторам пока не определены**: владелец каталога
  объявит их до открытия продаж.

## 8. Обновления и отзыв

- Новая версия — тот же путь (шаги 4–6) с тем же ключом автора. Владельцы ботов получают уведомление и обновляют
  кнопкой; если разрешений стало больше, бот снова спросит согласия.
- Плагин можно убрать из каталога: у тех, кто его поставил, он продолжит работать, в `/market` будет пометка «убран из
  каталога» и кнопка «Удалить».
- Вредную сборку каталог отзывает: боты останавливают и удаляют её сами при ближайшей проверке, владельцу — причина.
